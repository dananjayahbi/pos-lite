# Tenant-aware favicon

The ERP favicon is generated by `src/app/icon.tsx` (Next.js metadata icon
route) and uses the tenant's configured `Tenant.logoUrl` instead of a fixed
AyurPOS mark. The static `src/app/favicon.ico` was removed so browsers consume
the dynamic icon rather than the old default.

## Tenant resolution order

1. `x-tenant-slug` header — set by `src/proxy.ts` for `*.ayurpos.com`
   subdomains.
2. Request `Host` matched against `Tenant.customDomain` (white-labelled admin
   domains), then against the `.ayurpos.com` subdomain slug.
3. The signed-in session's `tenantId`.
4. The first active tenant, which keeps the login page and other
   unauthenticated requests working.

## Rendering

- The logo is fetched server-side (3 s timeout) and embedded as a data URL, so
  `ImageResponse` never resolves a remote image mid-render.
- PNG/JPEG/WebP/GIF up to 2 MB are accepted.
- A missing logo, unsupported format, network failure or a misconfigured URL
  falls back to the tenant name's initial letter on the existing espresso tile.
- The route is `force-dynamic` because the answer depends on request headers
  and the session.

`/icon` and `/apple-icon` are in the proxy's `PUBLIC_PATH_PREFIXES`; browsers
request favicons without a guaranteed session, and the icon must still resolve.

## Verification

- `npx tsc --noEmit`
- `npx vitest run`
- Signed in to a tenant with a logo: the browser tab shows that logo.
- Signing in to another tenant changes the icon without a redeploy.
